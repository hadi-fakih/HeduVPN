      Two commands, one ordinary HTTPS port.
      
      
      HeduVPN is a self-hosted VPN built to keep working on networks that block VPNs. It does not use WireGuard, OpenVPN, PPTP or a proprietary handshake on an unusual port. It speaks TLS 1.3 on 443, uses WebSocket or a native TLS record stream, pads its records and answers probes with a normal website.
      
      
      
        
      
          
      1 · On your VPS
      
          
      python -m heduvpn relay --domain vpn.example.com --port 443
      
          
          
      Prints a hedu1:// link and keeps running. Needs ports 80+443 open, a DNS record, and root (or setcap) for 443. A Let's Encrypt certificate works too: --cert/--key.
      
        
      
        
      
          
      2 · On your machine
      
          
      python -m heduvpn client --link "hedu1://…"
      
          
          
      Starts a local SOCKS5 proxy on 127.0.0.1:1080 with automatic reconnects and session rotation. Add --http-proxy 8080 for an HTTP CONNECT proxy.
      
        
      
      
      
      
      This dashboard
      
      
      python -m heduvpn dashboard --port 8000
      
      
    
      

    
      
      
      How it avoids blockers
      
      
      
        
      
          
      Blocker techniqueHeduVPN response
      
          
            
      Block non-standard VPN portsEverything rides TCP/443 using TLS 1.3, with optional WebSocket inside.
      
            
      Protocol fingerprintingNo OpenVPN/WireGuard/PPTP signatures. The only outer protocol is TLS, plus HTTP/1.1 upgrade when in WebSocket mode.
      
            
      SNI filteringConnect through your own domain, optionally fronted by a CDN. The SNI looks like any other site you host.
      
            
      Certificate / CA inspectionClients pin the certificate fingerprint. No public CA needed, and no VPN vendor name anywhere in the chain.
      
            
      Active probingUnknown HTTP requests get nginx-style 200/404/400 pages. WebSocket upgrades require a short-lived HMAC gate token; without it the path is a plain 404.
      
            
      Replay of captured handshakesThe gate token expires in two minutes; the tunnel handshake is a fresh AEAD exchange under a 256-bit PSK with timestamp checks.
      
            
      Packet-size analysisRecords are padded (random or 256-byte cells), payload length never appears on the wire, and jitter decorrelates timing.
      
            
      Idle-pattern detectionOptional cover traffic keeps an idle tunnel statistically similar to a live WebSocket app.
      
            
      Long-session correlationSession rotation replaces the transport periodically; every session gets fresh ChaCha20-Poly1305 keys.
      
            
      Legacy device / DPI applianceWebSocket mode survives reverse proxies, CDNs and most middleboxes because it is ordinary HTTP traffic.
      
                
        
      
      
      
    
      

    
      
      
      
        
      What no VPN can hide
      
        
        
          
      • The destination IP. A determined censor that blocks your relay's IP will block it. Mitigate with CDN fronting, rotating relays, or a relay in a friendly network.
        • 
          
      • Total traffic volume and long-term flow shape. Padding hides record sizes, not the fact that you transferred 4 GB today.
        • 
          
      • Client-side compromise. Malware, keyloggers, or a hostile OS see plaintext before it enters the tunnel.
        • 
          
      • Legal and policy risk. Using a VPN can be restricted or illegal where you live. This tool is for privacy, research and access to information — you remain responsible for how you use it.
        • 
        
      
      
      
      
      
        
      Operations notes
      
        
        
          
      • Keep the PSK secret: it is the only credential. Rotate it by regenerating the link.
        • 
          
      • The relay blocks private/loopback targets and SMTP ports by default; adjust allow_private, allow_ports, block_ports deliberately.
        • 
          
      • Behind a CDN: run the relay with tls: false on a loopback/private port, let the CDN terminate TLS, and import a link with verify: system.
        • 
          
      • Run the dashboard on loopback. It can export your full configuration including the PSK.
        • 
          
      • Wire-level counters are metadata only; HeduVPN never logs payload bytes.
